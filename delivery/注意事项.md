# crewAI GaussDB 适配 — 注意事项（避坑清单）

> 来源：适配全程的实测记录（lessons）。开发/运维/二次开发前必读。

## 1. 认证：开源 psycopg2 与 sha256

GaussDB 默认认证 `sha256` 是**自研挑战应答协议**（非标准 SCRAM），开源 `psycopg2-binary` 无法连接（报 `SASL authentication mechanisms are not supported`）。官方自研驱动 whl 仅 Python 3.11/Linux，与本项目 Python 3.10~3.13 冲突。

**解法（实例侧一次性配置）**：
```bash
# 三节点开 md5 双存储（1 = sha256+md5）
gs_guc reload -Z coordinator -D <CN 数据目录> -c "password_encryption_type=1"
gs_guc reload -Z datanode  -D <DN 数据目录> -c "password_encryption_type=1"
# gs_hba 对应用户/网段改 md5 后 reload
# 重置密码使新格式生效（新旧密码不能相同，两步换回原值）
```

## 2. Oracle 兼容（O 模式）SQL 方言约束

适配层已全部处理；**二次开发写 SQL 时必须遵守**：

| 约束 | 说明 | 替代 |
|---|---|---|
| ❌ `INSERT ... ON CONFLICT` | O 模式语法错误（仅 PG 兼容库可用） | `MERGE INTO`（见 `crewai.gaussdb.vector.upsert_via_merge`） |
| ❌ BOOLEAN 列经 jsonb 载荷批量写 | `text→boolean` 无隐式赋值 cast（A/ORA 双模式实测） | SMALLINT 0/1 |
| ❌ TEXT 值直接入 JSONB 列 | `text→jsonb` 无隐式赋值 cast（实测） | `upsert_via_merge(cast_columns={"col": "jsonb"})` |
| ❌ `#>>` 操作符 / GIN 索引（ustore） | O 模式不支持 | `->`/`->>` 链；JSONB 过滤走 `->>` |
| ❌ `gen_random_uuid()` / `uuid_generate_v4()` / `MAX(uuid)` | 无 pgcrypto / UUID 聚合不支持 | 应用层 `uuid4()`；`MAX(col::text)` |
| ⚠️ 空字符串 → NULL | DDL 默认值与运行时 DML 都生效 | NOT NULL 列禁 `DEFAULT ''`；写入侧空串占位（适配层已处理） |
| ⚠️ VARCHAR(n) 按字节 | UTF-8 中文 3 字节/字符 | 中文可能的列用 TEXT 或留余量 |
| ⚠️ REAL 类型行为未验证 | 本适配用 DOUBLE PRECISION | — |
| ⚠️ DATE 受 `mapping_date_to_datea` GUC 影响 | 新装库默认 on | 本适配时间全部用 ISO 文本（VARCHAR）绕开 |
| ⚠️ 分布式：外键/生成列（IDENTITY）不支持；唯一约束须在分布键上（否则依赖 GSI，仅 GTM-LITE） | 形态级差异 | 主键即分布键（适配层表设计已遵守）；自增用 SEQUENCE |
| ✅ 实测可用 | MERGE INTO（含 jsonb 载荷批量）、SEQUENCE、INSERT RETURNING、JSONB `->>`/`@>`、ILIKE、LIMIT/OFFSET、BOOLEAN（直接参数）、to_char | |

## 3. 向量专属

- `floatvector` 列 **NOT NULL**（不支持 NULL）；维度建表时固化，上限集中式 4096 / 分布式 1024（建表级）
- 只有 `ORDER BY col <+> %s LIMIT k` 形态走向量索引
- GsDiskANN 建索引前必须 `SET maintenance_work_mem='512MB'`（**值带单引号**；默认 64MB 不够）
- `pq_nseg` 必须整除维度（1536→96、3072→96、4096→128，`calc_pq_nseg` 自动处理）
- GsIVFFLAT 数据增删超 20% 建议重建索引
- `enable_vectordb=off` 时建索引报 "supported only by high-order features"——开启即解除
- 并发 `CREATE INDEX IF NOT EXISTS` 有 race（pg_class 唯一键冲突）——调用方须持 `store_lock`

## 4. 并发与锁

- 写路径（save/update/delete/reset/ensure）持 `crewai_core.lock_store` 锁（锁名 `gaussdb:{host}:{port}:{db}[:scope]`）；读路径无锁（与 SQLite 版惯例一致）
- 单机：portalocker 文件锁（锁文件在系统 temp——**不同 TMPDIR 的进程间失去互斥**）
- 跨机：必须设置 `REDIS_URL` 启用分布式锁
- 池连接上的会话级 GUC（probe/maintenance_work_mem）随连接存活——search 已在每次查询前补 SET，纯查询进程召回质量不受影响

## 5. 安全

- `GAUSSDB_PASSWORD` 全链路 `exclude=True`：不进 repr、model_dump、checkpoint payload（checkpoint 会序列化整个 CheckpointConfig.provider 链——已实测封堵）
- 从 checkpoint 恢复的 provider 密码为空时自动从 `GAUSSDB_PASSWORD` 环境变量回填
- 测试凭据一律 `.env`（git-ignored），交付文档只用占位符

## 6. Windows 开发环境（测试相关）

- `pytest-recording --block-network` 拦 Windows asyncio socketpair → 涉及 `asyncio.run` 的测试加 `@pytest.mark.block_network(allowed_hosts=[r"127\.0\.0\.1", r"localhost", r"::1"])`
- SQLite 临时目录 teardown 的 `PermissionError WinError 32` 是 crewAI 既有问题（连接引用环），与适配无关
- 控制台打 emoji 报 GBK 错 → `PYTHONUTF8=1`
- 全量回归必须 `-n 0` 串行（xdist 并行 DDL 竞态）

## 7. 工程环境（uv/镜像）

- `uv.lock` 固化 `files.pythonhosted.org` URL：`UV_DEFAULT_INDEX` 在 `--frozen` 下**不生效**；每次 `uv lock` 后必须重跑 sed 重写为镜像 URL（清华源路径结构一致、哈希不变）
- `uv sync` 不含 optional-dependencies——开发环境 `uv sync --extra gaussdb`，否则 venv 里的 psycopg2 会被移除
