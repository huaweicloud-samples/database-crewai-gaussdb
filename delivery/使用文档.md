# crewAI GaussDB 适配 — 使用文档

> 面向使用者：如何在代码中启用 GaussDB 作为 crewAI 的存储后端。
> 部署前置与验证见 `实施部署交付文档.md`；坑与限制见 `注意事项.md`。

## 1. 安装

```bash
pip install "crewai[gaussdb]"
```

## 2. 连接配置

```bash
export CREWAI_STORAGE_BACKEND=gaussdb
export GAUSSDB_HOST=...
export GAUSSDB_PORT=5432
export GAUSSDB_USER=...
export GAUSSDB_PASSWORD=...
export GAUSSDB_DATABASE=...
```

或使用 python-dotenv 的 `.env`（模板见 `.env.gaussdb.example`）。

## 3. 关系持久化（Flow 状态 / Kickoff 输出 / Checkpoint）

设置 `CREWAI_STORAGE_BACKEND=gaussdb` 后**自动生效**，无需改代码：

- `@persist` / `Flow(persistence=...)` 的状态落 GaussDB（表 `flow_states` / `pending_feedback`）
- Kickoff 任务输出（表 `latest_kickoff_task_outputs`）
- `CheckpointConfig(location="gaussdb")` 显式指定时 checkpoint 落 GaussDB（表 `checkpoints`）

显式注入（等价）：

```python
from crewai.flow.persistence.gaussdb import GaussDBFlowPersistence

flow = MyFlow(persistence=GaussDBFlowPersistence())
```

Checkpoint 用法：

```python
from crewai.state.provider.gaussdb_provider import GaussDBProvider
from crewai.state.checkpoint_config import CheckpointConfig

config = CheckpointConfig(location="gaussdb", provider=GaussDBProvider())
# checkpoint 返回 location 形如 "gaussdb#<id>"，CLI crewai checkpoint list/info/prune gaussdb 可读
```

CLI 读取（同一开关）：`crewai checkpoint list gaussdb` / `info` / `prune`、`crewai log-tasks-outputs`。

## 4. Memory 记忆

```python
from crewai import Agent, Crew

crew = Crew(..., memory=True, embedder=my_embedder)  # Crew 内部 Memory
# 或独立使用：
from crewai.memory.unified_memory import Memory

memory = Memory(storage="gaussdb", embedder=my_embedder)
memory.remember("用户偏好中文交流")
hits = memory.recall("用户偏好什么语言")
```

`embedder` 接受任意 `Callable[[list[str]], list[list[float]]]`（如 Ollama/OpenAI 的 API 包装）。

行为要点：
- 记忆表 `memories`，向量列维度由**首次写入**的 embedding 推断并固化
- 检索 `score = 1 - cosine_distance`（与 Qdrant 后端一致），复合评分（semantic/decay/importance）在 Python 侧
- scope 前缀过滤走索引；换 embedding 模型（维度变化）会抛 `EmbeddingDimensionMismatchError`，需 `memory.reset()` 重建

## 5. Knowledge / RAG

```python
import crewai.rag as rag
from crewai.rag.gaussdb.config import GaussDBRagConfig

rag.config = GaussDBRagConfig(
    embedding_function=my_embedder,   # 必填：GaussDB 后端无本地默认 embedder
    database="mydb",                  # 其余 GAUSSDB_* 默认值可覆盖
)
```

之后正常使用 Knowledge（全局配置自动生效，含 `Agent(knowledge_sources=...)` 链路）：

```python
from crewai.knowledge.knowledge import Knowledge
from crewai.knowledge.source.text_file_knowledge_source import TextFileKnowledgeSource
from pathlib import Path

kn = Knowledge(
    collection_name="mydocs",
    sources=[TextFileKnowledgeSource(file_paths=[Path("/abs/path/doc.md")])],
)
kn.add_sources()
results = kn.query(["问题"], results_limit=5, score_threshold=0.6)
```

行为要点（与 chromadb 对齐的部分 + 有意差异）：
- doc_id 缺省 = `sha256(content + "|" + json.dumps(metadata, sort_keys=True))`——同 id 覆盖（upsert）
- `score = clamp(1 - 0.5 × cosine_distance, 0, 1)`——与 chromadb 公式一致，`score_threshold` 默认行为保持
- `limit` / `batch_size` 来自 config 对象（BaseRagConfig 字段），kwargs 显式传入优先
- metadata 过滤：dict 等值（键值参数化，JSONB `->>` 实现）；不支持 chromadb 的 where/where_document 高级语法
- **文件路径必须传 `pathlib.Path` 对象**（str 会被拼上 `knowledge/` 前缀）
- 表名 = `crewai_rag_<collection_name 消毒后>`；每 collection 一表

## 6. Embedding 维度指引

| 部署形态 | 上限 | 索引（自动选择） |
|---|---|---|
| 集中式 | 4096 | ≤1024 维 GsIVFFLAT；1025~4096 维 GsDiskANN+PQ |
| 分布式 | **1024**（CREATE TABLE 硬限） | GsIVFFLAT |

常用模型参考：bge-m3（1024，两形态可用）、text-embedding-3-small 设 `dimensions=1024`（两形态可用）、text-embedding-3-large（3072，仅集中式）。

前置：实例 `enable_vectordb=on`（见实施文档 §2）。

## 7. Ollama 本地模型（示例）

```python
import json, urllib.request

def ollama_embed(texts: list[str]) -> list[list[float]]:
    req = urllib.request.Request(
        "http://127.0.0.1:11434/api/embed",
        data=json.dumps({"model": "bge-m3", "input": texts}).encode(),
        headers={"Content-Type": "application/json"},
    )
    with urllib.request.urlopen(req, timeout=120) as resp:
        return json.loads(resp.read())["embeddings"]

rag.config = GaussDBRagConfig(embedding_function=ollama_embed)
```

LLM（Crew/Agent/Memory 的提取与分析）：`LLM(model="ollama/qwen3:4b", base_url="http://127.0.0.1:11434")`。
