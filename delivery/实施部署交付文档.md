## 二、前置条件（部署前确认）

| 条件 | 要求 | 检查方式 |
|---|---|---|
| GaussDB 版本 | Kernel 507+ | `SELECT version();` |
| 兼容模式 | Oracle 兼容（集中式 `DBCOMPATIBILITY='A'`，分布式 `'ORA'`） | `SELECT datcompatibility FROM pg_database WHERE datname='<库>';` |
| 数据库 | 已建库（兼容模式建库时确定，不可后改） | `CREATE DATABASE <库名> DBCOMPATIBILITY='A';` |
| 向量前置（仅向量功能） | `enable_vectordb=on`（POSTMASTER 级，需重启集群） | `SHOW enable_vectordb;`；开启：`gs_guc set -Z coordinator -Z datanode -N all -I all -c "enable_vectordb=on"` 后 `cm_ctl stop && cm_ctl start` |
| 认证 | 开源 psycopg2 可连（md5 或已验证的认证配置；默认 sha256 需按注意事项 §1 调整） | `python -c "import psycopg2; ..."` 连通测试 |
| 用户权限 | 目标库 CREATE TABLE / INDEX / SEQUENCE / COMMENT | 建表冒烟 |
| Python | 3.10 ~ 3.13（crewAI requires-python） | `python --version` |
| 维度计划（仅向量） | 集中式 embedding ≤4096 维 / 分布式 ≤1024 维 | 按选型 embedding 模型确认 |

## 三、安装与配置

### 3.1 安装

```bash
pip install "crewai[gaussdb]"        # 或 uv sync --extra gaussdb（源码部署）
```

`crewai[gaussdb]` = `psycopg2-binary>=2.9.12`，无其他新依赖；不安装该 extra 时 crewAI 默认行为（SQLite/LanceDB/chromadb）完全不变。

### 3.2 环境变量

复制 `delivery/.env.gaussdb.example` 为 `.env`（或导出到进程环境），填写真实凭据。完整变量表：

| 变量 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `CREWAI_STORAGE_BACKEND` | 持久化切换必填 | — | 设为 `gaussdb` 启用关系持久化切换 |
| `GAUSSDB_HOST` | 是 | localhost | |
| `GAUSSDB_PORT` | 是 | 5432 | |
| `GAUSSDB_USER` | 是 | — | |
| `GAUSSDB_PASSWORD` | 是 | — | 不参与任何序列化（安全契约） |
| `GAUSSDB_DATABASE` | 是 | crewai | |
| `GAUSSDB_MIN_CONNECTIONS` / `GAUSSDB_MAX_CONNECTIONS` | 否 | 1 / 10 | 连接池 |

### 3.3 三种启用方式（按需组合）

| 功能 | 启用方式 | 关闭方式 |
|---|---|---|
| 关系持久化（Flow 状态/Kickoff 输出/Checkpoint） | `CREWAI_STORAGE_BACKEND=gaussdb` | 不设该变量（默认 SQLite） |
| Memory 记忆 | `Memory(storage="gaussdb")` | 默认 `storage="lancedb"` |
| Knowledge / RAG | `crewai.rag.config = GaussDBRagConfig(...)`（模块属性赋值） | 默认 chromadb |

三者的连接信息都读 `GAUSSDB_*` 环境变量；`GaussDBRagConfig` 也可在构造时显式传参覆盖。

## 五、运维要点

| 主题 | 说明 |
|---|---|
| 向量索引维护 | GsIVFFLAT 数据增删超 20% 建议重建索引（召回率下降）；重建即 DROP INDEX 后由应用下次写入自动重建 |
| GsDiskANN 建索引内存 | 需要 `maintenance_work_mem ≥ 512MB`（应用在建索引会话自动 SET；实例级默认 64MB 不够） |
| 维度变更 | 换 embedding 模型（维度不同）→ Memory 抛 `EmbeddingDimensionMismatchError`，需 reset 重建；Knowledge 需删除对应表 |
| 密码安全 | `GAUSSDB_PASSWORD` 被 exclude 序列化——永不进入 checkpoint payload / repr / dump |
| 跨机部署锁 | 多机共享同一 GaussDB 时，写并发串行化依赖 `REDIS_URL`（crewAI lock_store）；单机文件锁即可 |
| 版本升级 | crewAI 后续版本升级时，本适配的接口面（StorageBackend/BaseClient Protocol + 工厂注册）是官方扩展点，适配代码随 fork 迁移 |

## 六、已知限制

1. 分布式实例 embedding 维度硬限 **1024**（CREATE TABLE 级，与索引无关）——高维模型需集中式或降维
2. Oracle 兼容（O 模式）SQL 方言约束见 `注意事项.md` §2（BOOLEAN 列经批量 upsert 不可用、空串→NULL 等——均已在适配层处理，列出供二次开发参考）
3. `GaussDBClient.metadata_filter` 仅支持 dict 等值过滤（chromadb 的 where/where_document 高级语法不支持）
4. CLI checkpoint 命令的 `diff` 子命令未接 GaussDB 分支（list/info/resume/prune 已支持）
5. xdist 并行跑真库集成测试有 DDL 竞态——测试约定 `-n 0` 串行（见测试指南）
